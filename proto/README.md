# proto — контракты системы

Единственный источник правды для межсервисного взаимодействия. Из этих файлов
генерируется код и для Python-сервисов, и для Go — руками структуры нигде не пишутся.

## Зачем это нужно именно здесь

Главная боль разноязычного проекта — рассинхрон контрактов. Переименовали поле в
Python-сервисе, Go-сервис об этом не узнал и упал на разборе JSON где-то в проде.

С protobuf такая ошибка ломает **сборку**, а не рантайм: Go просто не скомпилируется,
если поля нет. Находится за секунды вместо часа отладки распределённой системы.

Побочный эффект — документация, которая не может устареть, потому что из неё
собирается код. Для отчёта по ПР4 это готовое описание всех межсервисных связей.

## Структура

```
proto/mirea/
├── common/v1/    Money, TimeRange, постраничная навигация
├── core/v1/      CoreService      — организация, филиалы, сотрудники
├── catalog/v1/   CatalogService   — услуги, цены, нормативы расходников
├── booking/v1/   BookingService   — записи и визиты
├── client/v1/    ClientService    — контакты и лояльность
├── events/v1/    доменные события RabbitMQ (10 штук)
└── realtime/v1/  эфемерные сообщения NATS
```

Четыре gRPC-сервиса — ровно те, к которым кто-то обращается. `inventory`, `billing`,
`notification` и `analytics` серверов не поднимают, они только клиенты.

## Кто кого вызывает

| Вызов | Метод |
|---|---|
| `booking → core` | `GetEmployeeSchedule`, `GetBranch` |
| `booking → catalog` | `GetService` |
| `inventory → catalog` | `GetConsumptionNorms` |
| `billing → booking` | `GetAppointment` |
| `billing → client` | `AddLoyaltyPoints` |
| `client → booking` | `ListClientAppointments` |
| `notification → client` | `GetClientContacts` |
| `analytics → core` | `GetBranch`, `ListEmployees` |

## Генерация

Через [`buf`](https://buf.build) — обёртка над `protoc`, избавляющая от возни с
путями и плагинами. Конфиги `buf.yaml` и `buf.gen.yaml` в корне репозитория.

```bash
buf lint          # проверить стиль
buf generate      # сгенерировать gen/go и gen/python
buf breaking --against '.git#branch=main'   # не сломали ли контракт
```

Сгенерированный код лежит в `gen/go` и `gen/python` и **коммитится в репозиторий**.
Обычно генерируемое в git не хранят, но здесь наоборот выгоднее: проект собирается
без установки `buf`, а изменения контракта видны в диффе рядом с кодом, который их
использует. `gen/go/go.mod` тоже живёт там и `buf` его не трогает.

После каждой правки `.proto` — `buf generate`, и сгенерированное уходит в тот же коммит.

## Правила, которые нельзя нарушать

**Номера полей — это и есть контракт.** В бинарном формате передаётся номер, а не
имя. Поэтому поле можно свободно переименовывать, но менять или переиспользовать
номер нельзя: старый читатель разберёт данные неправильно и не заметит этого.
Удалили поле — номер уходит в `reserved` навсегда.

**Ломающие изменения — только через новую версию пакета.** Рядом с `catalog/v1`
появляется `catalog/v2`, старые клиенты продолжают работать. `buf breaking` в CI
не даст сломать это случайно.

**Деньги — целое число копеек.** `Money.amount_kopecks`, никаких float: округление
при делении даст расхождение в отчётах, и искать его придётся долго.

**Enum начинается с `_UNSPECIFIED = 0`.** В proto3 нулевое значение неотличимо от
отсутствующего, поэтому нулём обязано быть «не задано», а не осмысленный вариант.

## События и NATS

`events/v1` описывает то, что летит в RabbitMQ. В очередь сообщения кладутся в
**protobuf-JSON**, а не в бинарном виде: типы остаются общими для обоих языков, но
сообщения читаются глазами в management-панели. На отладке это окупается.

События намеренно тонкие — несут идентификаторы, а не полные снимки. Потребитель
запрашивает детали по gRPC (так `billing` тянет визит из `booking`). Payload не
разрастается, и его не приходится версионировать при каждом изменении карточки.

`EventEnvelope.traceparent` прокидывается вручную: иначе трасса рвётся на брокере и
в Jaeger события выглядят несвязанными корнями. Это единственное место, где два
брокера стоят дополнительной работы по ПР10.

`realtime/v1` — сообщения NATS. Гарантий доставки нет, и это осознанно: они
устаревают за секунды, подписчик ресинкнется при переподключении.
