# catalog-service

Справочник услуг: что оказываем, сколько это стоит, сколько длится и что
расходуется на процедуру.

| | |
|---|---|
| **Язык** | Python 3.12 + FastAPI |
| **БД** | PostgreSQL, `catalog_db` |
| **Транспорт** | REST наружу, gRPC-сервер внутрь |
| **Порты** | REST :8002, gRPC :9002 |
| **Автотестов** | 13 |

## Ответственность

**Владеет:** услугами, ценами по филиалам, длительностью процедуры, справочником
материалов и **нормативами расхода** — сколько граммов краски уходит на окрашивание.

**Не владеет:** остатками на складе (`inventory-service`). Здесь норматив «сколько
должно уйти», там факт «сколько есть и сколько ушло».

Норматив связывает услугу со складом и делает списание автоматическим: после
завершённой записи `inventory` спрашивает норматив и списывает материалы сам.

## REST API

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/services` | Завести услугу вместе с нормативами расхода |
| `GET` | `/services/{service_id}` | Карточка услуги |
| `GET` | `/branches/{branch_id}/services` | Прайс филиала |
| `PUT` | `/services/{service_id}/price` | Изменить цену |

Отдельного эндпоинта для материалов нет намеренно: администратор мыслит услугой
(«на окрашивание уходит 60 г краски»), а не справочником. Материалы заводятся по
ходу создания услуги и переиспользуются по названию.

## gRPC

Сервер, `proto/mirea/catalog/v1/catalog.proto`:

| Метод | Кто вызывает | Зачем |
|---|---|---|
| `GetService` | booking | Длительность и цена при создании записи |
| `GetConsumptionNorms` | inventory | Что и сколько списать после записи |

`branch_id` в `GetService` — не фильтр, а проверка: услугу нельзя запросить от
имени чужого филиала, иначе получишь `NOT_FOUND`.

## События

Ничего не публикует и не потребляет. Чистый справочник, меняется только руками
администратора — не каждый сервис обязан быть в шине.

## Как устроен код

Раскладка ровно как у `core-service`: `infra/` — каркас, `models.py`, `commands.py`,
`domain.py` — предметная область, `api/` и `rpc/` — транспорты.

Из восьми файлов `infra/` семь скопированы из `core-service` **байт в байт**.
Отличается только `config.py` — префикс переменных окружения, порты и DSN.

## Грабли SQLAlchemy

`get_service` использует `populate_existing=True`. Без него после `commit` объект
остаётся в identity map, `session.get` возвращает кэшированный экземпляр с
незагруженными связями, и обращение к ним вне async-контекста даёт `MissingGreenlet`.

Причём падает не транзакция, а сериализация ответа — данные при этом уже записаны.
Клиент получает 500, а услуга в базе есть.

## Запуск

```bash
docker compose up -d catalog-service   # REST :8002, gRPC :9002
```

## Тесты

Два вида: unit и интеграционные.

```bash
.venv/bin/python -m pytest
```

**Unit** — инвариант нормативов в агрегате: один материал дважды это опечатка,
а не двойной расход.

**Интеграционные** — против настоящего Postgres в базе `catalog_db_test`:
переиспользование материалов между услугами, изоляция филиалов, прайс, смена цены.
